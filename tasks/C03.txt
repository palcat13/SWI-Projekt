SWI · Cvičení C03 — Část A: Zmapujte současnou realizaci jednoho scénáře
Úterní předstih / první část společného C03

Cíl

Pochopit, jak současná implementace skutečně realizuje jeden scénář z C02, a připravit ověřený
AS-IS podklad pro návrh architektury.

V tomto průchodu se naučíte

  - sledovat scénář od specifikace až do konkrétního kódu;
  - rozlišit business krok od technických detailů implementace;
  - identifikovat části systému, které scénář realizují;
  - zjistit, kde je stav uložen a kde se rozhoduje o jeho změně;
  - dohledat, kde se v implementaci vynucuje business pravidlo / invariant;
  - identifikovat relevantní externí a perzistenční závislosti;
  - vytvořit jednoduchý AS-IS strukturální pohled podle skutečného kódu;
  - formulovat konkrétní architektonickou otázku založenou na evidenci.

Vycházíte ze Specification Baseline v0.2 a běžící aplikace z C02.

Použijte jeden scénář, který už máte ve v0.2. Doporučený je `Confirm Reservation`; pokud je pro váš
tým architektonicky zajímavější schvalování, použijte příslušný scénář s approval.

Výstup Části A

Do docs/architecture-and-decisions.md vložte:

  1. odkaz na použitý scénář a související požadavky/pravidla;
  2. mapování hlavních kroků scénáře na konkrétní kód;
  3. mapování jedné důležité alternativní/chybové větve;
  4. seznam hlavních částí implementace, které scénář realizují;
  5. kde je stav uložen, kdo rozhoduje o změně stavu a kde se vynucuje jedno důležité pravidlo;
  6. relevantní externí/perzistenční závislosti;
  7. jeden AS-IS strukturální diagram;
  8. jednu konkrétní otázku pro další architektonický návrh.

A2. Namapujte hlavní průchod scénáře na kód

A4. Vyberte hlavní části implementace

Z kroků A2–A3 vyberte části kódu, které scénář skutečně realizují. Typicky půjde o 3–7 částí.

Použijte pokud možno stejnou úroveň detailu:
  - buď konkrétní třídy, pokud je aplikace malá;
  - nebo logické skupiny/moduly, pokud scénář prochází větším počtem tříd.

Pokud jeden blok sdružuje více tříd, uveďte pod ním, které třídy do něj patří.

Vyplňte:

  | Část implementace   | Typ / obsah                          | Role v tomto scénáři | Doklad |
  | `Reservation API`   | `ReservationController`              | přijme command       | ...    |
  | `Reservation logic` | `ReservationService`, `Reservation`  | rozhodne potvrzení   | ...    |
  | `Persistence`       | `ReservationRepository`, ...         | načte/uloží stav     | ...    |

A7. Nakreslete AS-IS strukturální diagram

Diagram má ukázat současnou realizaci zvoleného scénáře, ne cílový návrh.

Postup
  1. Nakreslete obdélník Application code.
  2. Dovnitř vložte 3–7 bloků z A4.
  3. Každý blok musí mít:
       - název;
       - krátkou roli v tomto scénáři;
       - pokud jde o skupinu, uveďte pod diagramem konkrétní třídy/moduly, které obsahuje.
  4. Databázi a externí systémy nakreslete mimo Application code.
  5. Nakreslete pouze vazby, které jsou pro zvolený scénář skutečně použité.
  6. Každou důležitou šipku popište slovesem/operací: confirm, load/save Reservation,
     send notification, validate token, ...
  7. Směr šipky musí odpovídat skutečnému směru volání nebo závislosti.
  8. Nemíchejte bez vysvětlení jednu konkrétní třídu s celou vrstvou. Pokud používáte různé úrovně
     detailu, označte typ bloku (class, module, external system, database).

Příklad formy

  +------------------------- Application code --------------------------+
  |                                                                      |
  |  [Reservation API]                                                   |
  |  role: accepts confirm command                                       |
  |          | confirm(id)                                               |
  |          v                                                           |
  |  [Reservation logic]                                                 |
  |  role: decides confirmation                                          |
  |       | load/save Reservation        | send notification             |
  |       v                              v                               |
  |  [Persistence]                 [Notification integration]            |
  |                                                                      |
  +----------------------------------------------------------------------+
          | read/write                         | HTTP/API
          v                                    v
   [Reservation DB]                  [Notification Service]

Pod diagramem můžete doplnit:

  Reservation API:
  - ReservationController

  Reservation logic:
  - ReservationService
  - Reservation

  Persistence:
  - ReservationRepository
  - SqlReservationRepository

A8. Formulujte jednu otázku pro další C03

Otázka musí vycházet z konkrétního nálezu v A2–A7.

Použijte:

  | Položka        | Obsah |
  | Otázka         | ...   |
  | Doklad         | ...   |
  | Proč je důležitá | ... |

  | Položka          | Obsah                                                                        |
